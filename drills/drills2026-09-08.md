## Exercício 1 — `len` + `sum`

### Enunciado
Você recebeu uma lista com as notas de um aluno.

Calcule:
- quantas notas existem;
- a soma de todas as notas;
- a média.

**Entrada:**
```python
notas = [7.5, 8.0, 6.5, 9.0]
```

**Saída esperada:**
```text
Quantidade: 4
Soma: 31.0
Média: 7.75
```

**Restrição:** não usar `for` ou `while`.

### Sua resposta
```python
def conta_notas(notas):
    quantidade = len(notas)
    soma = sum(notas)
    media = soma/quantidade

    print(f"Quantidade: {quantidade}")
    print(f"Soma: {soma}")
    print(f"Média: {media}")

notas = [6.0, 7.0, 8.0]
conta_notas(notas=notas)
```

### Avaliação
**Dentro do esperado:** Sim.

Você usou `len()` e `sum()` diretamente, sem reimplementar contagem ou soma manualmente.

**Tentativas até a solução correta:** 1.

## Exercício 2 — `max` com `key`

### Enunciado
Você recebeu uma lista de produtos no formato `(nome, preço)`.

Encontre o produto mais caro.

**Entrada:**
```python
produtos = [
    ("Mouse", 120),
    ("Teclado", 250),
    ("Monitor", 900),
    ("Webcam", 300)
]
```

**Saída esperada:**
```text
Produto mais caro: Monitor - 900
```

**Restrição:** não usar `for` nem `while`.

### Primeira resposta
```python
def acha_produto(produtos):
    print(f"Produto mais caro: {max(produtos, key=lambda x : x[1])}")
```

### Avaliação
**Dentro do esperado:** Parcialmente.

O uso de `max(..., key=...)` estava correto, mas a saída era:
```text
Produto mais caro: ('Monitor', 900)
```

em vez do formato pedido.

### Ajuste feito
Você tentou:
```python
def acha_produto(produtos):
    print(f"Produto mais caro: {max(produtos, key=lambda x : x[1])[0]} - {max(produtos, key=lambda x : x[1])[1]}")
```

Isso produziu a saída correta, mas chamou `max(...)` duas vezes.

A forma idiomática sugerida seria desempacotar o resultado uma única vez:
```python
nome, preco = max(produtos, key=lambda x: x[1])
```

### Resultado
Você não chegou a reenviar essa versão final porque o tempo do exercício acabou, mas entendeu o ajuste necessário.

**Tentativas realizadas:** 2.

```python
def acha_aluno(alunos):
```

## Exercício 6 — `any` e `all`

### Enunciado
Você recebeu uma lista de temperaturas.

Descubra:
- se alguma temperatura passou de `30`;
- se todas as temperaturas são maiores que `0`.

**Entrada:**
```python
temperaturas = [18, 22, 31, 27, 15]
```

**Saída esperada:**
```text
Alguma acima de 30: True
Todas acima de 0: True
```

**Restrição:** não usar `for` ou `while` como statements. Generator expressions são permitidas.

### Primeira resposta
```python
def acha_temp(temperaturas):
    print(f"Algo acima de 30: {any(t > 30 for t in temperaturas)}")
    print(f"Todos acima de 0: {all(t > 30 for t in temperaturas)}")
```

### Avaliação
**Dentro do esperado:** Não completamente.

A primeira condição estava correta, mas a segunda verificava `t > 30` em vez de `t > 0`.

### Ajuste feito
```python
def acha_temp(temperaturas):
    print(f"Algo acima de 30: {any(t > 30 for t in temperaturas)}")
    print(f"Todos acima de 0: {all(t > 0 for t in temperaturas)}")
```

### Avaliação final
Correto e idiomático.

**Tentativas até a solução correta:** 2.

## Exercício 7 — `enumerate`

### Enunciado
Você recebeu uma lista de tarefas.

Imprima cada tarefa com sua posição, começando em `1`.

**Entrada:**
```python
tarefas = ["Estudar Python", "Treinar", "Ler"]
```

**Saída esperada:**
```text
1 - Estudar Python
2 - Treinar
3 - Ler
```

**Regra:** usar `enumerate`. Não criar contador manual.

### Primeira resposta
```python
def ordena_tarefas(tarefas):
    for c, tarefa in enumerate(tarefas):
        print(f"{c+1} - {tarefa}")
```

### Avaliação
**Dentro do esperado:** Funcional, mas havia uma forma mais idiomática.

### Ajuste feito
```python
def ordena_tarefas(tarefas):
    for c, tarefa in enumerate(tarefas, start=1):
        print(f"{c} - {tarefa}")
```

### Avaliação final
Correto e idiomático.

**Tentativas até a solução correta:** 2.

## Exercício 11 — `Counter`

### Enunciado
Você recebeu uma lista com nomes de frutas vendidas.

Conte quantas vezes cada fruta aparece.

**Entrada:**
```python
frutas = [
    "maçã",
    "banana",
    "maçã",
    "laranja",
    "banana",
    "maçã"
]
```

**Saída esperada:**
```python
{
    "maçã": 3,
    "banana": 2,
    "laranja": 1
}
```

**Regra:** usar `Counter` de `collections`. Não fazer contagem manualmente.

### Primeira resposta
```python
from collections import Counter

def conta_frutas(frutas):
    dic = {}
    conta = Counter(frutas)

    for fruta in frutas:
        dic[fruta] = conta[fruta]

    return dic
```

### Avaliação
**Dentro do esperado:** Funcional, mas não idiomático.

O `Counter` já havia feito todo o trabalho; o segundo `for` era redundante.

### Segunda tentativa
```python
from collections import Counter

def conta_frutas(frutas):
    conta = Counter(frutas)
    return conta
```

Essa versão era idiomática, mas imprimia:
```text
Counter({'maçã': 3, 'banana': 2, 'laranja': 1})
```

e o exercício esperava um `dict` comum.

### Ajuste final
```python
return dict(conta)
```

### Avaliação final
Correto e compatível exatamente com o tipo de saída esperado.

**Tentativas até a solução correta:** 3.

## Exercício 13 — modificar uma coleção dentro do `for`

### Enunciado
Você recebeu uma lista e quer dobrar todos os valores alterando a própria lista original.

**Entrada:**
```python
numeros = [1, 2, 3, 4]
```

**Saída esperada:**
```python
[2, 4, 6, 8]
```

Comece tentando:
```python
for n in numeros:
    n = n * 2
```

O objetivo era entender por que reatribuir `n` não altera os elementos da lista.

### Sua resposta
```python
def dobra_numeros(numeros):
    for n in numeros:
        n = n*2

    print(numeros)
```

### Resultado observado
A lista permaneceu:
```python
[1, 2, 3, 4]
```

### Avaliação
**Dentro do esperado:** Sim, porque o objetivo era errar de propósito e entender o motivo.

Você identificou a ideia central: alterar `n` não significa alterar o slot da lista.

A explicação foi refinada para:
- `n` referencia o valor atual;
- `n = n * 2` faz `n` passar a referenciar outro inteiro;
- a lista continua contendo as referências originais;
- para alterar a lista de fato, é necessário escrever em `numeros[indice]`.

### Ajuste discutido
```python
for c, n in enumerate(numeros):
    numeros[c] = n * 2
```

Também foi discutido que uma list comprehension cria normalmente uma nova lista:
```python
[n * 2 for n in numeros]
```

### Resultado
O exercício foi concluído conceitualmente.

**Tentativas:** 1 tentativa intencional + discussão da correção.

## Exercício 14 — filtrar enquanto percorre a própria lista

### Enunciado

**Entrada:**
```python
numeros = [3, -1, 5, -2, 0, 8, -4]
```

**Saída esperada:**
```python

```

Comece tentando:
```python
for n in numeros:
    if n < 0:
        numeros.remove(n)
```

O objetivo era entender por que remover elementos da mesma lista que está sendo percorrida pode causar comportamento inesperado.

### Sua resposta
```python
def remove_negativos(numeros):
    for n in numeros:
        if n < 0:
            numeros.remove(n)

    print(numeros)
```

### Resultado observado
Neste exemplo específico, a saída foi a esperada.

### Avaliação
**Dentro do esperado:** Sim, como experimento, mas a estratégia não é segura de forma geral.

Você percebeu corretamente que, quando um elemento é removido, os índices dos elementos seguintes mudam.

No caso original, os valores assumidos por `n` foram:
```text

-1
-2
8
-4
```

Os valores `5` e `0` foram pulados. O resultado só ficou correto porque os valores pulados não precisavam ser removidos.

Com negativos consecutivos, o bug apareceria.

### Forma idiomática sugerida
Criar uma nova lista filtrada com list comprehension.

### Resultado
Exercício concluído conceitualmente.

## Exercício 18 — `Counter` + `max`

### Enunciado
Você recebeu uma lista de votos.

Descubra qual opção recebeu mais votos.

**Entrada:**
```python
votos = ["A", "B", "A", "C", "B", "A"]
```

**Saída esperada:**
```text
Mais votado: A
```

**Regra:** usar `Counter` e `max(..., key=...)`. Não fazer contagem manual.

### Primeira resposta
```python
from collections import Counter

def conta_votos(votos):
    contagem = dict(Counter(votos))
    candidato, votos = max(contagem, key=lambda x : contagem.values())

    print(f"Mais votado: {candidato}")
```

### Avaliação
**Dentro do esperado:** Não.

Havia dois problemas:
1. `key=lambda x: contagem.values()` devolvia todos os valores, em vez da contagem associada à chave atual;
2. `max(contagem, ...)` retorna apenas uma chave, então não deveria ser desempacotado em duas variáveis.

### Ajuste identificado
Você chegou à expressão correta:
```python
max(contagem, key=lambda x : contagem[x])
```

Essa expressão retorna:
```python
"A"
```

Logo, o resultado deve ser guardado em uma única variável, como `candidato`.

### Resultado
A correção conceitual foi alcançada após o tempo do exercício.

**Tentativas até identificar a expressão correta:** 2.

## Exercício 20 — revisão combinada

### Enunciado
Você recebeu uma lista de vendas no formato `(vendedor, valor)`.

Faça duas coisas:
1. calcule o total vendido;
2. encontre o vendedor responsável pela maior venda individual.

**Entrada:**
```python
vendas = [
    ("Ana", 120),
    ("Bruno", 300),
    ("Carla", 180),
    ("Diego", 250)
]
```

**Saída esperada:**
```text
Total vendido: 850
Maior venda: Bruno - 300
```

**Regras:**
- usar `sum(...)`;
- usar `max(..., key=...)`;
- não usar `for` separado nem acumulador manual.

### Sua resposta
```python
def calcula_vendas(vendas):
    print(f"Total vendido: {sum([valor for _, valor in vendas])}")

    nome, valor = max(vendas, key=lambda x : x[1])

    print(f"Maior venda: {nome} - {valor}")
```

### Avaliação
**Dentro do esperado:** Sim.

A solução estava correta. A única melhoria sugerida foi evitar criar uma lista intermediária no `sum`.

### Ajuste sugerido
Em vez de:
```python
sum([valor for _, valor in vendas])
```

usar uma generator expression:
```python
sum(valor for _, valor in vendas)
```

### Avaliação final
Correto e idiomático após essa micro-otimização.

**Tentativas até a solução correta:** 1.

## Padrões que mais apareceram

Os principais pontos de melhoria observados foram:

- evitar recalcular `max()` ou `min()` várias vezes;
- usar desempacotamento de tuplas quando a estrutura dos dados já é conhecida;
- confiar no que a biblioteca padrão já produz (`Counter`, `sum`, `len`, etc.);
- evitar criar listas intermediárias desnecessárias quando uma generator expression basta;
- entender a diferença entre reatribuir a variável de um `for` e modificar a coleção;
- evitar alterar o tamanho de uma lista enquanto ela está sendo percorrida;
- usar recursos próprios de funções como `enumerate(..., start=1)` em vez de fazer ajustes manualmente.
